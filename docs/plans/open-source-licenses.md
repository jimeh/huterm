# Open source licenses plan

Status: approved

## Objective

Users can read the license of every piece of open source software Huterm
ships, from a Licenses button in the About panel, on macOS and Linux. The
content matches what the running build actually contains.

## Constraints

- One committed notices artifact, regenerated by a Mise task and guarded by a
  drift check in `mise run verify` and CI. No new tools: `cargo tree`,
  `cargo metadata`, Bun, and the existing `cargo deny` license audit.
- The artifact covers all four release targets (`aarch64-apple-darwin`,
  `x86_64-apple-darwin`, `x86_64-unknown-linux-gnu`,
  `aarch64-unknown-linux-gnu`). Each entry records the targets that ship it.
  Today macOS and Linux share 245 of 424 shipped crate versions.
- The same file ships in `Huterm.app` and in both Linux packages, byte for
  byte. The AppImage and tarball payloads must stay identical.
- Keyboard operations stay catalog commands bound under a key context
  (desktop client guide). No new global key bindings.
- Leave the CI workflow change to one step, because another thread is editing
  workflows.

## Approach

### Generator (`scripts/licenses.ts`, `mise run licenses:generate`)

1. Run `cargo fetch --locked`, then `cargo tree` per target to get the
   shipped set, and `cargo metadata` for license expressions, manifest
   directories, and repository URLs.
2. Parse each SPDX expression, treating legacy `/` as `OR`. `AND` keeps every
   operand. `OR` picks one alternative: first one the crate ships a file
   for, in the order MIT, Apache-2.0, BSD-3-Clause, BSD-2-Clause, ISC, Zlib,
   then any. Failing that, an alternative with a committed canonical text,
   for licenses without a per-work copyright line (Apache-2.0, CC0-1.0).
   Failing that, a committed clarification. Otherwise generation fails and
   names the crate.
3. Classify license files by name (`LICENSE-MIT`, `LICENSE-APACHE`, ...),
   by the single license of a one-license expression, or by signature
   phrases. A combined file matches every license it contains. A file whose
   name contradicts its wording fails generation; an unrecognized file under
   several declared licenses ships as a notice. Apache-2.0 also carries the
   crate's `NOTICE` file.
4. Clarifications (`third-party/licenses/crates.json`) cover crates that ship
   no file for a license that needs one, such as objc2 and taffy. Each one
   pins the upstream URL at the crate's VCS commit, a SHA-256, and a caret
   version range. Crates whose repository has no license file either get the
   standard MIT text naming their Cargo.toml authors.
5. Non-crate components come from `third-party/licenses/components.json`:
   id, name, version, license, URL, targets, an optional condition
   (`macos-updater` or `appimage`), and files as repository paths,
   `crate:<name>/<path>`, or `packaged:<file>` references.
6. Normalize layout only: LF line endings, trimmed trailing spaces, tabs
   expanded, and surrounding blank lines removed. Deduplicate texts by
   SHA-256.
7. Write `third-party/licenses/licenses.json`, sorted with a stable order.
   `mise run licenses:check` regenerates in memory, compares bytes, and fails
   with the regenerate command. It runs in `verify:parallel` and in CI's
   Policy job.

### Packaging

- macOS: a packager resource puts the artifact at
  `Contents/Resources/licenses.json`. `package:macos:bundle` asserts that it
  is byte-identical to the committed file.
- Linux: the package policy gains a `licenses.json` notice entry in
  `share/licenses/huterm/`, next to the Debian copyright files it references.
  The existing byte check covers it, in both the tarball and the AppImage.

### Runtime (`huterm-gpui`)

- `src/licenses.rs` is pure data with no GPUI. It holds the serde model, the
  lookup order (the macOS `Resources`, then `share/licenses/huterm` relative
  to the executable, then the source-tree copy for unpackaged builds), the
  filter for this build (target, `macos-updater` feature, `APPIMAGE`, and
  packaged files that exist), and the search.
- Loading runs on the background executor when the view opens. Errors become
  an unavailable state; they never panic.
- `desktop/licenses.rs` holds the `LicensesView` entity: search `TextField`,
  list, and detail.

### Experience

- **About panel:** a Licenses button on the footer's left, with Copy Details
  and Close on the right. Tab, Shift-Tab, Left, and Right move focus between
  the three buttons. Focus starts on Close, so Enter still closes, and the
  focused button shows the existing focus ring. Enter activates the focused
  button and Escape closes.
- **Choice: an in-app view, not the system viewer.** It matches Hubris Voice
  and Hubris Share, works the same on both platforms, needs no `open` or
  `xdg-open` and no viewer for JSON, and works inside an AppImage mount. The
  view replaces the About panel inside the same modal layer and scrim, as a
  sheet over the About page. Done or Escape returns to About with focus on
  Licenses.
- **Layout:** a panel of `min(viewport - 32, 860)` by
  `min(viewport - 32, 600)`. Header: the title "Open Source Licenses" and a
  search field. Body: on the left, a list of name plus version, with the
  license in muted text. On the right, a detail pane with the name, version,
  declared license, "used under X" when an `OR` was resolved, the kind, a
  Website button that opens the URL, a Copy button, and each text under its
  file name in monospace, scrolling. Footer: an entry count, key hints when
  `shortcut_hints` is on, and Done.
- **Keyboard:** the view root takes the `Palette` key context, so the
  existing palette and text bindings apply without new bindings:
  - typing filters by name, version, license, or kind;
  - Up, Down, Ctrl-N, and Ctrl-P change the selection;
  - Page Up and Page Down scroll the license text;
  - Escape clears a non-empty search, then returns to About;
  - Enter and Tab do nothing.

  The Palette-scope router sends commands to the licenses view while it is
  open. The workspace keeps `confirming`, so terminals stay blocked.
- **Pointer:** clicking a row selects it. The wheel scrolls the list and the
  text, and both have scrollbars. The scrim blocks the terminal, as in About.
- **States:**
  - while loading, the body shows "Loading licenses…";
  - when the file is unavailable, it shows "License information isn't
    available in this build." and the expected location;
  - when nothing matches, it shows "No matches for "x"";
  - when the window is narrow, the list column shrinks to between 180 and
    260 px and the text wraps.
- Theme colors come from `Swatch`, as in About. GPUI exposes no
  accessibility tree for these custom elements, so that is a known
  limitation, as it already is for About.

## Observable success

- In About, the Licenses button opens a list of the components this build
  ships. On macOS that includes no Linux-only crates, and on Linux no
  AppKit crates. Selecting one shows its full license text.
- Both `mise run package:macos` and the Linux container packages contain
  `licenses.json`, byte-identical to the committed file, and the packaged
  app shows it.
- A dependency, toolchain, or notice change without regeneration fails
  `licenses:check` locally and in CI.

## Failure paths and risks

- A crate without an identifiable license text fails generation with its
  name and the fix: a clarification or a canonical text.
- A crate bump outside a clarification's range fails generation instead of
  shipping stale text.
- A missing or corrupt artifact shows the unavailable state, and About still
  works.
- A missing `packaged:` file at runtime hides that entry. Dev builds bundle
  none of those libraries.
- Large texts: each entry's text renders only while it is selected, and the
  list renders a few hundred fixed-height rows.
- Release Please changes only workspace crate versions, which the artifact
  excludes, so release PRs do not drift.

## Non-goals

- Text selection inside the license text. The Copy button covers that need.
- A separate window, a menu bar item, or a new catalog command for licenses.
- Licenses of system libraries Huterm links but does not ship, such as glibc,
  Vulkan, AppKit, and XCB core.
- Automatic regeneration in Dependabot or refresh PRs.

## Deviations

- The artifact lives at `third-party/licenses/licenses.json`, beside its
  inputs, rather than at `third-party/licenses.json`.
- Six crates (objc2 0.6, objc2-encode, block2, objc2-foundation 0.3, seahash,
  block) have no license file upstream either. Their clarification is the
  standard MIT text naming their Cargo.toml authors, and the entry's title
  says so.
